## 1. Implemented systems

### Simulation core (`src/sim/`)
| System | How it actually works |
|---|---|
| Loop | Fixed 60 Hz. `Run.step(TickInput)` advances exactly one tick; no wall-clock anywhere in `/src/sim`. |
| Determinism | Run = `RunConfig` + input log. End state is FNV-1a hashed over quantised positions/HP/RNG state, including class actives, VS boon picks and Core choice. `RunConfig.contentHash` fails a replay loudly against edited `/data` (G2). |
| RNG | mulberry32, five independent streams (`waves`, `spawns`, `drops`, `offers`, `ai`) seeded by FNV-1a of the stream name + run seed. |
| Math | `dsin`/`dcos`/`datan2` are polynomial; the sim never calls native trig. |
| Grid | 36×20 tiles, 3 gates (W/N/E), Core 2×2 east-center. Integer-cost Dijkstra produces a ground field and a ghost field toward the Core/Warden. |
| Sealing | Legal (§10): a structure tile is a high-cost passable tile (`breach.base + perEhp × effective max HP`), so a sealed board routes the cheapest breach and chews structures on the way; an open path is always cheaper. Fliers/Burrowers/Wraiths keep their bypasses. Gate G7. |
| Run structure | **The real §1.1 shape**: 18 TD waves + 6 VS waves, TD×3→VS repeating, `RunConfig.cycles` (default 6) gates how many TD/VS blocks a run has. TD wave 18 ends with the Gatebreaker miniboss; the final VS wave (block 6) ends with the Warden-Eater. Multi-summon stacks up to 3 TD waves (`maxStackedWaves`); every TD wave cleared pays a flat `20 + 10×wave` gold, early or not (fb009 — the old early-call bonus is gone). Leak coupling: each TD leak adds `2×` its spawn cost to the next VS wave's budget ("Loose in the dark: N"). Build phase 20 s; VS wave 75 s (final block runs to the boss kill). Gate G6. |
| Spatial index | One pooled bucket array per tile, rebuilt each tick. |
| Enemies | 20 defs (§9), trait behaviour dispatched off a cached bitmask. |
| Towers | 10 defs (§5), 7 attack kinds (`single`/`pierce`/`cone`/`aura`/`chain`/`lob`/`poison`). Flat per-step upgrade cost (not growing); sell refunds 50% of everything spent, in every phase. Gate G20 (every §5 milestone special measurably changes the attack it names). |
| Cores | 5 defs (§5.5): Stone Heart (default), Carnivorous Plant, Vampire Heart, Corpse, Time — chosen at run start, hashed into `RunConfig`, each with its own TD and VS effect and an upgrade track bought at the Core. Gates G21 (unit-tested numbers)/G22 (fingerprint shift)/G23 (T1 win rate). |
| VS inheritance | §6.1's formula, verbatim: a built tower type's VS attack damage is the average of its instances' damage (by upgrade level), boosted +10% per extra tower of that type; special effects and attack speed come from the highest-upgrade instance. VS attacks count as character attacks (lifesteal, on-attack passives apply). Gate G3. |
| Classes | 12 defs (§4): archetype bands + Passive + Active1 (Q) + Active2 (E) + always-on tower passive, per class. All actives are sim Commands. Swordsman/Archer/Engineer free; the other 9 unlock via quests. |
| Damage & stacking | 6 damage types + 2 statuses (§3, `data/damagetypes.json`), armor +99 cap / −100 floor (`reduction = clamp(a,-100,99)/100`), DoTs ignore armor, Burning shreds armor and stacks per-application (flipped from refresh-strongest at p10a) under the shared 50-stacks/enemy cap. Stacking: different sources multiply, same-source ranks add (§2). Gates G4/G5. |
| Equipment | 12 items (§7, one per weapon/armor/shoes/ring/necklace/bracelet slot), stash click-to-swap, `N` TD waves cleared → `N` equipment at run end. Gate G12. |
| VS level-up pool | §6.3: 1-of-3 cards per level, 1 free reroll; stat boons (uncapped rank, fb011), Type Mastery per built tower type, 3 skill cards per class. |
| Rewards & meta | TD wave cleared → equipment; VS wave cleared → skill point; 120-node Constellation (adjacency-gated, connectivity-preserving refunds); 24-slot stash; 10 unlock quests (§8.4); no currency-granting quests; Orbs/relics/Ember retired outright (G12's "orbs nowhere"). |
| Boss | The Warden-Eater: 3 phases at 100/66/30% HP (telegraphed charges shattering terrain, Wraith summons + slam rings, a closing fire-ring enrage). Gatebreaker (TD wave 18 miniboss, 2× vs structures). |
| Loot | Even-weight equipment drops per cleared TD wave. |

### Outside the sim
| System | How it actually works |
|---|---|
| Bots (`src/bots/`) | `idle`, `kite`, `turtle`, `hybrid`, `no-move`, `maxbuild`, `rush`, `walloff`, `greedy`, `greedless`, plus `sealed` (G7) and the `single:<tower>` builder used by `tools/a4probe.ts`/`a5probe.ts`. None issues class actives on its own — gate measurements that need a kit script it locally (`tests/p6e-class-diversity.test.ts`, `tests/p-core-f-gates.test.ts`). |

| Renderer (`src/render/`) | Canvas, backed at device pixel ratio, reads sim state only. Hit flash, damage numbers (per-damage-type color/font, `data/damagetypes.json`), shake, boss telegraphs, arena fire, the DoT-segment HP bar, a 2 s TD↔VS transition sweep (`w.fx`-driven, outside `hashWorld`). |
| SFX | Every gameplay event maps to a rate-limited synthesised cue behind an `AudioSink` seam; asset pass still pending (BETA). |
| UI (`src/ui/`) | Hub (class / Core / tier draft / Constellation / stash / settings) → run (canvas + HUD + modals, DPS summary panel, tower/weapon lineage panels, character panel with per-source stat breakdown) → results → Hub. Esc pauses and offers Abandon Run (confirm). |
| Headless CLI | `npm run sim` prints a JSON report per run: `simMs`, damage by source, per-wave telemetry. |
| Fast-forward | 1/2/3/10/50×; the renderer may skip frames at 10× and above but the sim steps the same fixed ticks, so a fast-forwarded run is bit-identical to the same run at 1×. |
| Practice runs | Kill all, +gold, +XP, heal, invulnerable, skip wave, +1 minute, summon boss — ordinary Commands gated on `RunConfig.practice`; a run that used one banks nothing. |
| Dev profile / god mode | `data/dev.json` unlocks every class/Core/map, memory-only (never persisted), production build has it off and god mode unreachable (G16). |
| Codex & Tuner | In-game wiki of every `/data` entity; in dev mode every number/wave is editable and saved to the real files via the dev-server, content-hashed into `RunConfig` (G2's tuner-edited-content clause); prod is read-only + export/import, with no save endpoint (G15). |
| Test seeding | Settings can fill an account with equipment/skill points, or wipe it, deterministically. |

### The wave-11-to-17 wall (the one root cause behind most of the above)
`data/waves.json` authors 18 real TD wave rows now (p8a closed the old
"repeats row 10 forever" gap), but the HP curve (`1.22^(wave−1)`) still
outpaces the economy every scripted bot/class/Core reaches by TD wave 11–17:
runs die `defeat_core` (leak accumulation) or `defeat_warden` (VS combat)
in that band almost independently of *which* class, Core, or tower mix is
driving. This is the single fact behind G8's 0/12, G14's 0/20, and G23's
4-of-5 red Cores — it is a **content-and-pacing gap, not eleven/five/one
independent balance stories**. It is P10's own gap to close, since P0–P9 are
done and content-complete (§2 above); no further P-band unlocks it.

### G13's structural remainder (frost_obelisk / ember_brazier over 35%)
`frost_obelisk`'s `aura` and `ember_brazier`'s `cone` wielded attacks hit
every enemy in range each interval; the other five kinds (`single`/`pierce`/
`chain`/`lob`/`poison`) hit only a line/arc/handful of targets. An
omnidirectional VS attack cannot be data-tuned below a directional one's
crowd damage without either overshooting `frost_obelisk`'s own T1/T3 solo
bar or undershooting T1 5/5 for one of the others (two rounds of
balance-analyst bisection confirmed this, moving the share 51.1%→46.0%→42.7%
without ever finding a value that clears 35%). Needs an engine-side fix
(BACKLOG p10j): give directional wielded attacks some crowd-relevant
behaviour of their own in VS.

### G1/G14 tension (why the boss fight isn't shorter yet)
Every `warden_eater` HP value low enough to land G1's 30–36 min band also
drives the scripted bot's win rate to 100% across every seed tried — which
directly contradicts G14's own "≥60% and <100%" text. `bossTimeSeconds`
600→181 (data-only, no gate conflict) closed most of the original 44.3 min
gap; the remaining ~1.15 min needs a pacing mechanism that shortens the
fight without also deciding its outcome (a DPS-race enrage timer, e.g.),
not a further HP/timer cut. Filed as BACKLOG p10k.

## 6. Engineer's list: what is shallow or missing

Most consequential first, written against SPEC-FINAL's actual 1.0 bar
(content is complete — §2 — so everything below is a balance or engine-depth
question, not a scope gap).

1. **The wave-11-to-17 wall is the single most consequential open problem**
   (§4). Every class, every Core but one, and the boss fight itself die to
   the same TD-economy-vs-HP-curve mismatch in the same six-wave band. Until
   it moves, G8/G14/G23 cannot move either, no matter how any one class or
   Core's own numbers are tuned — `tests/p6e-class-diversity.test.ts`'s
   Necromancer/Paladin retunes proved this directly (both moved from an early
   VS death onto the exact same wall as everyone else, without clearing it).

2. **VS-wielded attacks have no directional/omnidirectional balance lever**
   (§4, G13). `frost_obelisk`'s aura and `ember_brazier`'s cone are the only
   two towers whose VS attack is inherently crowd-shaped; the other five are
   single-line/arc, and no amount of `/data` tuning closes that gap without
   either breaking their own T1 viability or another tower's T3-fails bound.
   This is the one G13 clause that needs `src/sim` work, not `/data`.

3. **The boss fight's pacing and its win-rate gate pull against each other**
   (§4, G1×G14). A DPS-race enrage timer or a time-gated damage-taken ramp
   (splitting "time to engage" from "time to kill") is the shape that could
   satisfy both; a flat HP or timer number cannot.

4. **The registered bot roster has drifted from the content it plays
   against.** `maxbuild`, `kite`, `rush`, `walloff` and `greedless` all read
   0% win rate at T1 in the current sweep (§4) — they were tuned for an
   earlier, simpler Act I/Act II shape and never re-scripted for classes,
   Cores or the real 18-wave curve. `hybrid` alone carries every live gate
   that needs "a bot that plays and sometimes loses." A roster refresh (or a
   documented reason each one still exists) would make future sweeps more
   informative.

5. **`no-move` winning 75% of the time is either a genuine finding or a gap
   in the sweep's own realism** — worth resolving explicitly (does VS combat
   trivially reward standing still on a tower-heavy board?) rather than
   leaving it as an unexamined number in a table.

6. **`tools/gate-audit.ts`'s coverage map needs a re-derive.** It still lists
   G8 and G15 as `hole` after both gained live coverage (`p6e`, `p9c`), and

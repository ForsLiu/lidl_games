what the code **actually does** against **SPEC-FINAL.md** (the only current
spec — SPEC.md/SPEC-V2.md/SPEC-V3.md are superseded history), not what any
prior spec draft said. Every number here was measured or read out of `/data`
on 2026-09-03 at commit `0c67363` (regenerated by BACKLOG p11b; the previous

## 1. Implemented systems

### Simulation core (`src/sim/`)
| System | How it actually works |
|---|---|
| Loop | Fixed 60 Hz. `Run.step(TickInput)` advances exactly one tick; no wall-clock anywhere in `/src/sim`. |
| Determinism | Run = `RunConfig` + input log. End state is FNV-1a hashed over quantised positions/HP/RNG state, including class actives, VS boon picks and Core choice. `RunConfig.contentHash` is a function of `/data`'s own authored bytes (`Content.raw`, fixed at b044) so it fails a replay loudly against edited `/data` (G2), without false-failing on a loader/schema change alone. |
| RNG | mulberry32, five independent live streams (`waves`, `spawns`, `drops`, `offers`, `ai`, `RngSet`) plus three one-shot streams derived once from the seed and never snapshotted (`terrain`, `draft`, `draftpick`; `ONE_SHOT_STREAM_NAMES`, named at the 2026-09-03 lane merge) — all seeded by FNV-1a of the stream name + run seed. |
| Math | `dsin`/`dcos`/`datan2` are polynomial; the sim never calls native trig. |
| Grid | 36×20 tiles, 3 gates (W/N/E), Core 2×2 east-center. Integer-cost Dijkstra produces a ground field and a ghost field toward the Core/Warden. |
| Sealing | Legal (§10): a structure tile is a high-cost passable tile (`breach.base + perEhp × effective max HP`), so a sealed board routes the cheapest breach and chews structures on the way; an open path is always cheaper. Fliers/Burrowers/Wraiths keep their bypasses. Gate G7. |
| Run structure | **The real §1.1 shape**: 18 TD waves + 6 VS waves, TD×3→VS repeating, `RunConfig.cycles` (default 6) gates how many TD/VS blocks a run has. TD wave 18 ends with the Gatebreaker miniboss; the final VS wave (block 6) ends with the Warden-Eater. Multi-summon stacks up to 3 TD waves (`maxStackedWaves`); every TD wave cleared pays a flat `20 + 10×wave` gold, early or not (fb009). Leak coupling: each TD leak adds `2×` its spawn cost to the next VS wave's budget. **Build phase 15 s** (cut from 20 s at `p10l` — pure dead-time removal, does not touch any bot's TD economy or combat difficulty); VS wave 75 s (final block runs to the boss kill). Gate G6. |
| Spatial index | One pooled bucket array per tile, rebuilt each tick. |
| Enemies | 20 defs (§9), trait behaviour dispatched off a cached bitmask. |
| Towers | 10 defs (§5), 7 attack kinds (`single`/`pierce`/`cone`/`aura`/`chain`/`lob`/`poison`). Flat per-step upgrade cost (not growing); sell refunds 50% of everything spent, in every phase. Gate G20 (every §5 milestone special measurably changes the attack it names). |
| Cores | 5 defs (§5.5): Stone Heart (default), Carnivorous Plant, Vampire Heart, Corpse, Time — chosen at run start, hashed into `RunConfig`, each with its own TD and VS effect and an upgrade track bought at the Core. Gates G21 (unit-tested numbers)/G22 (fingerprint shift, `corpse`'s seed-2 regression fixed at `b071` — `storeRatio` 0.02→0.03)/G23 (T1 win rate — see §4, currently red on the over-ceiling side). |
| VS inheritance | §6.1's formula, verbatim: a built tower type's VS attack damage is the average of its instances' damage (by upgrade level), boosted +10% per extra tower of that type; special effects and attack speed come from the highest-upgrade instance. Directional wielded attacks (`single`/`pierce`/`lob`/`poison`) also carry a small engine-side crowd allowance (`wieldSplash`, `src/sim/vswield.ts`, landed at `p10j`) so no single tower type's VS share can structurally dominate. VS attacks count as character attacks (lifesteal, on-attack passives apply). Gate G3. |
| Classes | 12 defs (§4): archetype bands + Passive + Active1 (Q) + Active2 (E) + always-on tower passive, per class. All actives are sim Commands. Swordsman/Archer/Engineer free; the other 9 unlock via quests. |
| Damage & stacking | 6 damage types + 2 statuses (§3, `data/damagetypes.json`), armor +99 cap / −100 floor (`reduction = clamp(a,-100,99)/100`), DoTs ignore armor, Burning shreds armor and stacks per-application under the shared 50-stacks/enemy cap. Stacking: different sources multiply, same-source ranks add (§2). Gates G4/G5. |
| Equipment | 12 items (§7, one per weapon/armor/shoes/ring/necklace/bracelet slot), stash click-to-swap, `N` TD waves cleared → `N` equipment at run end. Gate G12. |
| VS level-up pool | §6.3: 1-of-3 cards per level, 1 free reroll; stat boons (uncapped rank, fb011), Type Mastery per built tower type, 3 skill cards per class. |
| Rewards & meta | TD wave cleared → equipment; VS wave cleared → skill point; 120-node Constellation (adjacency-gated, connectivity-preserving refunds); 24-slot stash; 10 unlock quests (§8.4); no currency-granting quests; Orbs/relics/Ember retired outright (G12's "orbs nowhere"). |
| Boss | The Warden-Eater: 3 phases at 100/66/30% HP (telegraphed charges shattering terrain, Wraith summons + slam rings, a closing fire-ring enrage), plus an independent damage-taken pacing ramp (`PACING_START`/`PACING_INTERVAL`/`PACING_VULNERABILITY_PER_STACK`, `src/sim/boss.ts`, landed at `p10k`) that shortens a long fight without moving the win/loss outcome. Gatebreaker (TD wave 18 miniboss, 2× vs structures). |
| Loot | Even-weight equipment drops per cleared TD wave. |
| Terrain generator (`src/sim/terrain/`) | Built and merged (`lane/terrain`, 2026-09-03) but **not wired into a real run yet** — every current run, including Training Grounds, still plays the flat arena. Per-seed procedural map (rough/rock/high tiles across 6 measured bands, structural 3-wide gate-to-plaza mains carved before scatter so connectivity holds by construction, a flagged flat-interior fallback after `maxAttempts` degenerate seeds). `data/terrain.json` is already inside `contentHash()` so wiring it later cannot open a replay hole (`tests/terrain-content-hash.test.ts`). SPEC-FINAL has no §10.5 for it yet (filed as **fb079**); wiring it into `World`/a run is **fb077**, blocked on three known-broken combinations the lane measured (the Fourth Gate modifier's south gate, 4/5000 seeds stranding the Core, nothing consuming `TerrainMap.fallback`) — see QUESTIONS Q162/Q164. |

### Outside the sim
| System | How it actually works |
|---|---|
| Bots (`src/bots/`) | `idle`, `kite`, `turtle`, `hybrid`, `no-move`, `maxbuild`, `rush`, `walloff`, `greedy`, `greedless`, plus `sealed` (G7) and the `single:<tower>` builder used by `tools/a4probe.ts`/`a5probe.ts`. None issues class actives on its own — gate measurements that need a kit script it locally (`tests/p6e-class-diversity.test.ts`, `tests/p-core-f-gates.test.ts`). |
| Meta (`src/meta/`) | Skill points → 120-node Constellation tree; 24-slot equipment stash; 10 quests; localStorage save with versioned migration and corrupt-save repair. |
| Renderer (`src/render/`) | Canvas, backed at device pixel ratio, reads sim state only. Hit flash, damage numbers (per-damage-type color/font, `data/damagetypes.json`), shake, boss telegraphs, arena fire, the DoT-segment HP bar, a 2 s TD↔VS transition sweep (`w.fx`-driven, outside `hashWorld`). |
| SFX | Every gameplay event maps to a rate-limited synthesised cue behind an `AudioSink` seam; asset pass still pending (BETA). |
| UI (`src/ui/`) | Hub (class / Core / tier draft / Constellation / stash / settings) → run (canvas + HUD + modals, DPS summary panel, tower/weapon lineage panels, character panel with per-source stat breakdown) → results → Hub. Esc pauses and offers Abandon Run (confirm). |
| Headless CLI | `npm run sim` prints a JSON report per run: `simMs`, damage by source, per-wave telemetry. |
| Fast-forward | 1/2/3/10/50×; the renderer may skip frames at 10× and above but the sim steps the same fixed ticks, so a fast-forwarded run is bit-identical to the same run at 1×. |
| Practice runs | Kill all, +gold, +XP, heal, invulnerable, skip wave, +1 minute, summon boss — ordinary Commands gated on `RunConfig.practice`; a run that used one banks nothing. |
| Dev profile / god mode | `data/dev.json` unlocks every class/Core/map, memory-only (never persisted), production build has it off and god mode unreachable (G16). |
| Codex & Tuner | In-game wiki of every `/data` entity; in dev mode every number/wave is editable and saved to the real files via the dev-server, content-hashed into `RunConfig` (G2's tuner-edited-content clause); prod is read-only + export/import, with no save endpoint (G15). |
| Test seeding | Settings can fill an account with equipment/skill points, or wipe it, deterministically. |

## 6. Engineer's list: what is shallow or missing

Most consequential first, written against SPEC-FINAL's actual 1.0 bar
(content is complete — §2 — so everything below is a balance or engine-depth
question, not a scope gap).

1. **G1/G8/G14/G23's over-ceiling inversion is the single most consequential
   open problem, and it is now four gates, not two.** The last regeneration
   only knew about G8 and G23; G14 has since been shown to share the same
   root cause once measured on the harness G8/G23 actually use, and G1's own
   87.5%-landslide margin makes its "green" reading fragile rather than
   solid. Four to five `/data`-only sessions found the wall is structural
   (shared-tower economy, near-zero-elasticity landslide floors) — this now
   needs an owner verdict (**QUESTIONS Q160/Q161**) on whether the bands, the
   scripted-kit-bot harness itself, or the shared-tower-vs-kit-damage
   balance is what should move, not another tuning attempt.

2. **G23's harness has a correctness bug independent of the tuning
   question** (§5, **p11a**) — three of five Cores can never pass as
   written, which understates how close a retune could actually get.

3. **G13's solo-viability clause is worse than either regeneration's raw
   assertion count suggests**, because the test's own pins have been
   lowered twice to track drift instead of the gate's real bar. A real
   `data/towers.json`-only retune (**fb076**) is queued but not started, and
   should also restore the share-cap clause's measurable pool size
   (**fb092**, newly filed this session) in the same pass, since `fb054`'s
   density change broke both.

4. **The terrain generator is a large, fully-tested, entirely inert
   system.** `src/sim/terrain/` and its 6-band data contract are built,
   merged, unit-tested and already inside `contentHash()`, but zero runs use
   it. Wiring it in (**fb077**) is the largest single piece of unclaimed
   scope in the queue right now — bigger than any remaining balance item.

5. **`p10z`'s margin-classification harness (`classifyMargin`/
   `summarizeMargins`, `tests/helpers.ts`) is new engine-adjacent
   infrastructure worth knowing about**: it turns a finished `RunReport`
   into `landslide-win`/`close-win`/`contested-loss`/`early-loss`/`timeout`
   without changing the engine, and is what let this and the last two
   sessions tell "everyone wins by a landslide" apart from "everyone wins a
   real fight" for the first time. Any future retune of G1/G8/G14/G23 should
   use it rather than a bare win/loss count.

6. **A recurring Windows flake family (fb087) has no fix yet** — scratch-dir
   `EPERM` under load and load-sensitive timeouts are cheap to keep
   dismissing individually but have now been independently rediscovered by
   three separate lanes in one week, which is itself a signal the retry/
   backoff fix is overdue.

**One structural note, unchanged from the v0.1 handoff and still true**: the
sim/render split and the data-driven content pipeline continue to hold up
well under a much larger content surface (12 classes, 10 towers, 5 Cores, 12
equipment items, 24 waves, and now a built-but-unwired terrain generator) —
every number above came from `/data` or a live measured test, not a
remembered one. What moved across the sessions this regeneration covers is
almost entirely balance-band tuning and measurement-harness accuracy (four
gates found to share one root cause, one harness bug found, one doc found to
have carried a stale "green" for a gate that had already gone red), plus one
large new system (terrain) landing without yet being load-bearing — not the
architecture.
